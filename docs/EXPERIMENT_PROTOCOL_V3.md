# Experiment protocol v3 — executable corrections with one audited repair

Status: **pre-registered / no inference started**.

## Question

When the same model, information, action contract, repair allowance, world, and
score are held constant, does persistent separation into specialized Theatre
roles improve paired annual economic performance relative to one general
manager that concentrates the same responsibilities?

## Why this is a new protocol

The official v2 campaign is immutable and terminal. All five pairs stopped at
structural gates before producing an economic result. Three Theatre failures
bound work that depended on future deliveries or sales as if it were executable
in the current turn; two control failures returned invalid structure. V3 does
not reinterpret or resume those seeds. It changes the prospective contract and
uses five new seeds.

## Intentional treatment difference

- Control concentrates critical audit, CFO/supply planning, operations, and
  autonomous strategic challenge in one persistent session.
- Theatre persists those responsibilities as Crítico, Consciência, Roteirista,
  and Personagem. Only Personagem submits business actions.

Both arms receive the same model, thinking level, simulator state, frozen
corpus, 14-action limit, cadence flags, score, and repair policy. Segmentation
remains the only intended capability difference.

## Executable-now versus conditional-future work

Every plan item declares exactly one timing class:

- `now`: its action is feasible from the current public state and is eligible
  for the current execution queue;
- `conditional_future`: it is not executable now and carries one observable
  precondition that must become true before a later turn may execute it.

A required critical correction may bind both classes, but every required
action type must be represented. All `now` correction items must be executed in
the same handoff. Conditional items must not be submitted early and are carried
as an audited future queue; they are not treated as current non-adherence.

## One structured repair

Each role invocation receives at most one repair only when the first response
is JSON-parseable but fails the frozen structural contract. The repair receives
the original response and deterministic validation errors, never a rival arm's
state or score. It must return a complete replacement object for the same role
and turn.

The original call and repair call are both preserved and charged. No simulator
transition occurs between them. A parse failure, transport failure, a second
structural failure, or any state/role/turn mismatch terminates `failed_contract`.
The allowance is identical in both arms and therefore measures the architecture
with one bounded self-correction capability, not first-response reliability
alone. Reports must disclose first-pass failures and repair outcomes separately.

## Cadence and causal order

Business decisions remain every three simulated days. Strategic review occurs
every nine turns and after a critical simulator event. Theatre order is Crítico
→ optional Consciência → Roteirista → Personagem. Consciência runs on the first
turn, every 18 turns, and when the Crítico returns `critical`. Control receives
the same flags and four-responsibility checklist in one response.

## Fixed exclusions and gates

- No human intervention, live internet, tools, connectors, file edits, or
  external messages from benchmark roles.
- No opponent state, opponent action, v1/v2 result, or aggregate in role
  context.
- No fallback model or API-key execution.
- Every submitted action maps to one `now` plan item and uses its declared type.
- Capacity used equals submitted actions and never exceeds 14.
- Critical corrections require action types and observable verification.
- Invalid structure receives at most one paid repair; no silent retry.
- Prompt, corpus, scenario, seed, cadence, score, repair policy, and gates are
  immutable after publication and before the five official pairs terminate.

## Frozen evidence and analysis

`preregistration/v3.json` freezes five new paired seeds, arm order, artifacts,
parity, cadence, timing contract, repair policy, score, and analysis. The audit
command recomputes every SHA-256 before pair creation or activation.

Publish every pair, including failure or bankruptcy, before aggregation. Show
paired economic differences, mean, median, Theatre seed wins, reliability, and
bootstrap interval. If the interval includes zero, the result is inconclusive.
Secondary and repair metrics explain mechanisms; they never replace the final
economic score.
